# KTV / ニコカラ显示规格与验收基准

本文是本项目的稳定验收基准。它区分最初调查阶段的 v1 范围、后来由用户明确升级的成片目标，以及当前实现和证据等级；不得以截图或“能显示”替代本规格。

## 1. 最初规范（调查阶段，历史事实）

最初目标是在 Project DIVA Mega Mix+ 的 PV 鉴赏模式实时叠加歌词，供 OBS 直接录制完整 PV。第一版要求：

- 行级时间；当前句、下一句和长空白区 `...`。
- 下一句默认提前 3000 ms 出现。
- 下方居中区域；清晰的描边/阴影；当前句与下一句有不同视觉强调。
- 不要求逐字、音节或渐进填充；不采用 ASS/libass；不做字幕编辑器或 DLL 热卸载。

这一阶段的任务仅限源码调查，明确禁止实现。该历史范围不能抹去，也不能被误写成当时已经决定采用逐字 KTV。

## 2. 当前生效规则（2026-10-11）

以下规则整合用户最近几轮调整，优先于旧状态记录中的“全曲行号交替”“最后 3 秒提示”“结束保留 3 秒”等描述。运行时长句缩字号规则见第 6 节；用户最新选择以整句时间保持不变为前提完成适配。

### 2.1 两行布局与段落

- 固定左上轨和右下轨，两轨字号、样式相同，左右安全边距镜像；“上轨”不永久等于当前句。
- 歌曲开场及每个长间奏后的新段落，第一句固定在上轨，第二句在下轨；段落内部继续上、下交替。
- 分段按时间间隔确定，不继承整首歌行号的奇偶。当前长间奏门槛为 8000 ms，即 6000 ms 预告 + 1500 ms 保留 + 500 ms 淡出，确保旧段显示结束与新段预告窗口不相交。
- 短停顿保持原段落顺序，不为每次停顿重置上轨。
- 每句位置由完整时间线确定，在预告、开唱、保留和淡出期间不跳轨；暂停、倒放或重新播放不依赖上一帧历史。
- 同一轨道的占用与交接按实际分段后的轨道关联，不能继续用行号减二推断。
- 邻近两句的间隔不超过 ktvPreCueMs（默认 3000 ms）时，在轨道可用的前提下一起预显示。

NicoKaraMaker 官方帮助将歌词组织为“页面”和“段落”，并根据显示时间间隔划分间奏前后的段落。本项目采用这一分段思路；8000 ms 门槛和上下轨重置是结合本项目时间窗口的具体设计，不宣称是所有 NicoKara 视频的统一标准。[官方帮助：页面、段落与自动区切](https://shinta.coresv.com/help/NicoKaraMaker2_JPN.html)

### 2.2 预告与圆点提示

- 首句与长空档只在下一句起唱前最后 6000 ms 内出现歌词和圆点；提前很久不得显示或闪烁圆点。
- 圆点指向紧接下来要唱的那句，放在该句所在轨道上方，尽量对齐其文本起点；下轨起唱时，提示点也在下轨。
- 圆点独立于 Ruby，不叠在读音上；整组保持在左右安全边距内。
- 保留原逐秒小圆点逻辑，尺寸与间距为旧版约 1.5 倍，并带深色描边；不改为巨大的圆圈。
- 每点对应一秒，末尾点随该秒淡出；开唱后提示消失。有当前演唱句时不额外显示下一句的倒计时。

### 2.3 透明度、结束状态与切换

- 整行淡入 500 ms；正常结束后保留 1500 ms，再淡出 500 ms。同轨后句在旧句淡完后开始自己的淡入。
- 密集短句根据同轨后句的时间缩短旧句停留，为前后各 500 ms 的透明过渡留出空间；极短句可能在起唱后才开始显影。
- 淡出保留已唱完的配色及进度，主歌词与 Ruby 一致；禁止清空ワイプ、改回未唱颜色后再淡出。
- 淡入淡出作用于主字、Ruby、描边、阴影和背景的整行合成结果，避免多层黑色描边累积造成“黑变白”。
- 已唱与未唱配色在互不重叠的裁剪区域绘制；歌词没有“未唱状态更透明”的额外硬切。
- 已唱部分继续按现有行级起止时间从左至右推进；颜色由用户配置，不强制覆盖已选择的青色、黄色或其他配色。

## 3. 字体、振假名与分辨率

- 歌词字号由用户选择，当前用户使用 94；不因一个长句擅自修改整首歌的字号设置。
- 歌词视觉以 1080p 为基准，随窗口高度同比缩放；4K 使用对应分辨率的字形图集。Ruby、描边、阴影和圆点同步缩放。
- 字体库已经接入本机 DFP 太丸ゴシック体 SB、EPSON 太丸ゴシック体 B；字间距过紧的 DFG/DFP POP Mix W5（用户称 P4）从模组字体列表排除。
- 保留已有字体与后备字体配置，不卸载 Windows 字体，不默认允许将商业字体随公开发行包再分发。
- Ruby 对齐所属 Unicode 汉字词组，短读音在词组内分布，过长读音缩小；主字换位、缩放或将来拆片时必须同步处理 Ruby。

## 4. 同步与数据边界

运行时使用已导出的完整 SRT → LyricLine 时间线，Ruby 从同名 TSV 加载；不以反应式原生事件猜测下一句。现有缓存已覆盖当前有效来源，较早只允许 PV424 的范围属于历史开发阶段。

行级起止时间可以驱动预告、整句均匀ワイプ、保留和淡出；不等于逐字/音节同步。无可靠字级时间时，禁止宣称精确逐字同步，禁止为长句自动拆片伪造准确演唱切点。

## 6. 超长歌词运行时缩字号（已实现）

### 6.1 宽度限制

按当前字体、用户字号、输出分辨率测量像素宽度，不设统一字符数。最大可用宽度为左右镜像安全边距之间的距离；测量包括实际字形伸出、Ruby、整数描边、正负阴影和可选背景，上下轨使用相同限制。预留分辨率对应的小幅像素余量，防止绘制取整造成越界。

以 1920×1080、左右各 8% 边距为例，基础区域约 1613 px。字体推进宽度、标点及装饰决定实际可容纳内容；4K 按相同比例适配。

### 6.2 每句临时字号

1. 能装下：使用用户选定的字号，当前设置 94 不变。
2. 超宽：只缩小这一句，直到整句及装饰能完整落在安全区；根据用户最新选择，不保留先前设计的 85% 下限。
3. 当前句和预显示下一句均采用同一测量算法，各自独立适配。预告、开唱、保留及淡出期间，只要字体、窗口和配置不变，该句尺寸和位置保持一致。
4. Ruby、描边、阴影、背景留白及ワイプ宽度随临时字号同比适配；提示圆点对齐适配后的待唱句起点。
5. 不修改字体配置、字体图集、SRT、Ruby 索引或整句起止时间。后面的短句自动使用原字号，不受上一句缩小影响。
6. 极长句可能缩得较小；目前优先完整显示。语义拆片与字级时间校准没有实现，不从现有整句时间伪造单字演唱切点。

截图对应 PV095 第 7 句“「おはよう」挨拶交わす君の頭上にねこみみ”，32.812–37.312 秒。在 1080p、94 号字、8% 边距、4 px 描边、3 px 阴影且无背景的真实字体检查中，EPSON 太丸ゴシック体 B 临时约 80.12，DFP 太丸ゴシック体 SB 临时约 91.05；后句“寝ぼけてるのさ”仍为 94。实际结果依当前字体、边距及装饰设置而定。

## 7. 最小验收循环

1. 运行 tools\build_ktv_render_regression.cmd，覆盖时间窗口、透明合成、段落、提示点，以及两种真实日文字体的长句宽度与安全边距。
2. Release/x64 构建及独立装载检查；游戏退出后备份、直接部署 DLL，并核验 SHA-256。
3. PV824：上段第 19 句结束于 1:43.992，第 20 句“近くの笑い声を”开始于 1:58.538，空档 14.546 秒。第 20/21 句应从 1:52.538 同步淡入，上下轨顺序为 20 上、21 下；提示点在上轨。
4. 短停顿：下一句在下轨时提示点也在下轨；开唱位置不跳动。
5. 已唱完歌词停留并整体淡出，Ruby 和已唱颜色不复位；长空档前六秒以外无提示点或提前歌词。
6. PV095 约 32.812–38.750 秒：94 号字下长句尾部、描边及振假名均应完整；下轨短句保留 94；预告转开唱时大小不跳变。另验不同日文字体及 1080p/4K。离线字形检查通过，游戏画面仍为 IN-GAME VERIFICATION REQUIRED。
