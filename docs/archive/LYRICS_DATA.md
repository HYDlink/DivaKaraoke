# 歌词时间线资料准入与后备计划

## 当前决定

正式 KTV 的优先数据源是 DIVA 原版 DSC 时间/歌词事件与原版 `pv_db.txt` 歌词数据库。PV276 已完成一首真实原版 PV 的数据关联验证；按 PVID 命名的 UTF-8 SRT：`lyrics/PV###.srt` 保留为原生时间线缓存缺失时的后备交换格式。

原生**显示 hook**只能在当前歌词事件发生后取得当前文本；它不能在首次播放前得知下一句及其开始/结束时间。因此显示 hook 只作为“没有完整时间线时的当前句降级显示”，不承担正式当前/下一句、3 秒预告、空白区或可靠ワイプ的时间来源。它不限制离线读取 DSC/pv_db 的可能性。

## 需要的最小数据

每首歌必须能够确定：

| 字段 | 必需 | 用途 |
| --- | --- | --- |
| PVID | 是 | 映射为 `PV###.srt`。 |
| 日文原文 | 是 | 正式显示内容。 |
| 每行开始时间 | 是 | 当前句出现、下一句预告。 |
| 每行结束时间 | 是 | 当前句结束、空白区及整句ワイプ。 |
| 时间基准 | 是 | 必须与 Mega Mix+ PV 播放时间一致或可验证转换。 |
| 来源与许可 | 是 | 决定能否纳入仓库或发布包。 |
| 翻译/罗马字 | 否 | 当前正式目标仅为日文，不阻塞 KTV。 |
| 字级时间 | 否 | 当前不实现逐字 KTV。 |

## 可接受来源与接入顺序

1. 已提取的原生 DSC + pv_db/等价歌词数据库；必须先证明事件、时间单位和 ID→日文文本映射。
2. 由验证过的原生提取器生成的版本化 JSON 时间线缓存。
3. 已有、可确认许可的 DIVA 歌词时间线资料；可转换为 SRT 后备。
4. 用户持有的 SRT、LRC、ASS 或其他带行级时间的数据；先在 `testdata/` 验证，再决定导入方式。
4. 人工校对的逐行时间文件；须注明资料来源和校对状态。

纯歌词文本、歌名数据库、当前句 hook 日志、没有时间戳的翻译 Mod 都**不满足**正式 KTV 数据条件。

## SRT 约定

- 编码：UTF-8（无 BOM 或带 BOM 均须由导入测试确认）。
- 文件名：`PV` + 三位或更多位 PVID + `.srt`，例如 `PV424.srt`。
- 时间：`HH:MM:SS,mmm --> HH:MM:SS,mmm`，以 PV 播放起点为 0。
- 文本：一条 SRT 事件对应一条 KTV 行；不在同一事件中混入下一句。
- 空白：由相邻事件的时间间隔推导，不伪造歌词行。
- 注释与元数据：不写入播放 SRT；另存为来源记录。

## 每个候选资料的验证清单

1. 确认 PVID 与游戏内调试面板一致。
2. 用至少三个点核对：首句、中段、尾句；误差、偏移方向和单位都记录下来。
3. 确认下一句在实际开始前 3000 ms 进入右栏。
4. 确认长前奏、间奏和尾奏显示 `...` 而非残留上一句。
5. 确认文本含日文汉字、假名、符号时能由部署字体显示。
6. 记录资料 URL/作者、许可或“许可未知”，再决定是否提交和发布。

## 用户提供候选资料后的最小任务

只做一首 PV 的“原生 DSC/pv_db 证据 → 三行手工时间线 → 游戏内三点核对”。通过后才实现最小离线提取器和 JSON 缓存；不要先写爬虫、通用资产框架、全量数据库或逐字系统。
