## 快速体验

启动游戏后按 Ctrl+G，在 Lyric 窗口进入“逐行歌手颜色”。当前第一、第二歌手的颜色配置默认展开。每位歌手独立设置：

- 未唱填充、未唱描边、已唱填充、已唱描边（完整四色）。
- 未唱阴影、已唱阴影。
- “保存歌手配色”立即保存到 singer-colors.toml；修改实时生效，无需重建字体或重新播放。
- “启用歌手配色”可立即与原默认配色对照。
- “合唱柔和渐变”可在渐变和融合纯色之间切换。

面板同时提供第一歌手、第二歌手、合唱的即时预览。建议先体验 Promise（本机F2nd覆盖版）及用户已校对的愛Dee，再看 erase or zero 的剧情口型误判。真实游戏布局、听感与录制效果仍需用户验收。

## 可复用工具

源码入口：scripts/build_singer_timeline.py。它读取已有PV JSON缓存中记录的DSC、文本表、opcode表，不按曲名猜资产，不扫描曲库、不重新解包、不修改SRT或Ruby，也不自动部署。

tools/build_singer_colors.cmd 在项目内可双击重跑六首样本。安装到模组tools后可传入同样的参数；缓存路径需要指向实际离线导出器生成的JSON。数据来源中保存的绝对路径必须仍可读取。

产物包括：

- PVnnn.singers.tsv：运行时歌手标记。
- PVnnn.singers.audit.json：输入哈希、角色表、姿态统计、分支、事件偏移及判定依据。
- PVnnn.singers.md：中文逐行结果。

命令示例，在项目根目录的Git Bash/Bash执行；反斜杠为续行符，PowerShell交互需改为反引号：

~~~bash
python scripts/build_singer_timeline.py \
  --cache artifacts/furigana-official-alignment/cache/PV062.json \
  --cache artifacts/furigana-official-alignment/cache/PV728.json \
  --output-dir artifacts/singer-mvp/cache \
  --verify-difficulties
~~~

阈值可通过 --min-events 调整，默认6。调整后只重新生成旁路，不修改原字幕。不要以某首歌的主观效果调阈值后声称已泛化到所有歌曲。

验证入口：

~~~bash
python scripts/verify_singer_mvp.py
~~~

## 自动策略及局限

2026-10-16补充：当前工具使用mouth-activity-v2；原六次门槛之外，只对整行未知增加持续/双槽同步活动补判。参数、审计字段与PV041/PV212真实漏标证据见[SINGER_EXPORT_WORKFLOW.md](SINGER_EXPORT_WORKFLOW.md#稀疏口型漏标修复)。本文六曲数量为最初MVP交付基线，当前结果以重新生成的审计为准。

1. 生产DSC读取器增加可选观察回调，接收已解码命令，原LYRIC/PV_END返回值保持不变；不写另一套parser，也不依赖Agent或临时行跟踪。
2. 角色表按缓存所记优先序合并；不一律排除GUEST，递归解析PSEUDO_SAME并去重身份；循环及未知角色不猜。
3. 支持当前两套基础姿态编号。只有文件主要采用另一套编号，且频率证据达到条件，才扩展来源专用活动姿态；它们是活动代理，不冒充音素语义。Promise覆盖版34/35/36占主体序列，与愛Dee偶发34/35不同，审计显式列出推测扩展。
4. 普通行要求至少6个活动事件，跨度至少120ms，并至少达到该行最活跃槽事件数的15%；小于1.2秒的短行要求至多3次，跨度门槛随行长缩小。没有固定裁掉句首/句尾，避免丢失愛Dee第39句的6次有效动作。
5. 成功/失败分支分别加上全局事件计算。两路径身份集合不同则保持未知，不能把两个互斥分支合并为合唱。
6. 只剩一个不同歌手身份时可由角色表归属，适用于六个初音复制角色。多人歌曲没有证据的行保持默认色。
7. 多人标记表示本行有多个角色参与候选，包括交替、插句、不同词重叠；不保证同词齐唱，也不提供字级时序。

当前是简单阈值MVP，不判断真实音频、原唱音色、歌词逐音素匹配或主唱/和声。动态频率扩展及剧情无声口型均可能误判。没有可靠数据就保留默认，是自动流程的一部分，不强制逐曲人工修订。

## 旁路格式及强绑定

~~~text
# singers-v1<TAB>62<TAB>28
# performer<TAB>0<TAB>RIN
# performer<TAB>1<TAB>MIK
1<TAB>21924<TAB>25402<TAB>RIN<TAB>原歌词全文
~~~

TAB代表实际制表符。每行字段为：有效行号、开始毫秒、结束毫秒、逗号分隔身份集合、歌词全文。未知集合写“-”。身份使用短ASCII标识，不限定六人或两个槽位。

运行时校验PVID、行数、每行唯一序号、起止时间及全文；任何一项不一致整份旁路不应用。歌词被用户修改、来源覆盖变化、时间轴改动时不会沿用错行标记。切歌、同曲重播和离开PV沿用原生命周期，清空旧身份。

## 配色与渐变

配色按MIK/RIN/LEN/KAI/LUK/MEI等身份键保存，不按槽位写死。自定义身份自动加入配置。默认分别为青绿、橙金、黄、蓝、粉、红；原默认颜色继续服务未标记行和禁用歌手配色时。

推荐方案是横向柔和融合：左端保留第一身份颜色、右端保留第二身份颜色，中间30%平滑过渡。三人及更多身份依次建立相邻过渡，同身份先去重。组合顺序沿用本曲角色表顺序，不随字幕左右轨道改变。

填充、描边、阴影均独立按未唱/已唱状态解析；各层支持不同颜色端点。可保持描边统一白/黑，仅让填充融合，提高辨识与可读性，也可在面板自由设置双色描边。

字体支持来自当前ImGui字形顶点着色：使用现有纹理UV，不改字体、不增加GPU shader、不重建字体图集。正文及Ruby共用整行渐变坐标，因此Ruby不会每个词重新开始渐变。渐变坐标不跟随ワイプ边界移动；未唱、已唱分开裁剪，淡出仍经原整行透明合成，歌词几何与时序不变。

真实日文字体EPSON/DFP、18/94/188字号字形、UV保持、三人组合、四色配置持久化与原DX11透明合成均已逻辑/渲染回归。人工查看的软件DX11渐变预览：artifacts/singer-mvp/gradient-preview.bmp。不是实际游戏截图。

## 构建、交付与部署

本轮不修改签名、Hook、逆向结构体、音频或OBS。统一Release/x64构建及独立DLL装载通过。

tools/deploy_singer_mvp.ps1 检查游戏已退出，核对六首安装SRT与已验证输入一致，保护有用户修改的歌手旁路，备份旧DLL及将替换的工具/旁路，直接安装，并逐份核对SHA-256。已有singer-colors.toml、freelyrics.toml、SRT/Ruby、字体及OBS设置不覆盖。运行时在未有歌手配置文件时使用默认配色，用户保存后生成独立配置。

部署状态、最终哈希、备份位置以 artifacts/singer-mvp/deployment.json 为准；本地实验包为 DivaSingerColors-MVP.zip。部署成功不能代替游戏内验证。

## 可行的后续方向（本轮不实现）

可以研究假名/罗马音音素序列与口型时间顺序对齐，定位小句或词组；口型元音与闭合姿态不能唯一确定所有字音，也不能判断原唱或音频版本。需要处理拉长元音、同音、跨行口型、动作插入与无声剧情表演。此方向有研究价值，但本轮仍保留整行均匀ワイプ，不伪造逐字时间。
